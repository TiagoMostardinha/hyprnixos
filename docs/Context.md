# NixOS + Hyprland + Quickshell — Claude Code Context

Oct 18, 2026 · @Share-me 👀

## Purpose and golden rules

This is the context file for Claude Code in my `nixos-config` repo: one flake that configures a NixOS laptop running Hyprland and a custom Quickshell desktop. It lives in `docs/`, which no config file imports, so editing docs never changes the deployment. Claude Code must follow these rules unless I say otherwise in chat.

1. **Simplicity over complexity.** Plain `imports` of plain files. No flake-parts, snowfall, haumea, or custom option frameworks unless I ask.
2. **One seam: hardware vs shared.** Anything tied to one physical machine lives in `hosts/<name>/`. Everything else is shared and must work on any laptop unchanged.
3. **One repo, one flake, one lockfile.** Home Manager runs as a NixOS module, so one `nixos-rebuild switch --flake .#<host>` applies system and user config together.
4. **Declarative only.** Never suggest `nix-env -i`, `nix profile install`, or imperative changes in `/etc` or `~/.config` that the repo doesn't own.
5. **Live-editable UI.** Hyprland and Quickshell config are real files in `dotfiles/`, symlinked out of the Nix store so they reload on save without a rebuild.
6. **Match the existing structure.** Before adding a file, check if an existing module is the right home. Ask before creating a new top-level folder.
7. **Verify before claiming done.** Run `nix flake check` and `nixos-rebuild build --flake .#<host>` (or `dry-build`) after Nix changes, and `hyprctl configerrors` after Hyprland changes.
8. **No comments.** Don't write comments in any config file (`.nix`, `.lua`, `.qml`, `.conf`, scripts). Names and structure must speak for themselves. Explanations go in chat or in `docs/`, never in the code.

The host's `home.nix` generates `~/.config/hypr/host.lua`; the shared `hyprland.lua` loads it with `dofile`, last, so it overrides the fallback monitor. That is why `dotfiles/hypr/` is linked file by file, not as one folder.

Add `secrets/` (sops-nix or agenix) only when the first real secret appears, and `lib/` or `profiles/` only when a second host makes duplication painful.

## NixOS and flakes policies

Every `.nix` file is a NixOS module; keep each one small, single-topic, and imported explicitly.

**Module system**

- A module has the shape `{ config, lib, pkgs, ... }: { imports = [ ]; config = { }; }`. Declare `options` only when a value is genuinely reused or toggled per host.
- Compose with `imports`. Lists such as `environment.systemPackages` merge automatically across modules, so add packages in the module that owns the feature, not in one giant list.
- Resolve conflicts with priority helpers, in this order of preference: `lib.mkDefault` in shared modules (so hosts can override), plain values in hosts, `lib.mkForce` only as a last resort with a comment saying why.
- Use `lib.mkIf` for conditional config and `lib.mkMerge` to combine conditional blocks. Never write `if … then … else` around a whole attribute set.
- A value must not depend on itself through `config` (infinite recursion). Read other modules' values via `config`, not by importing their files.
- Inspect final values with `nixos-rebuild repl --flake .#<host>` or `nixos-option`, instead of guessing.

**Flake**

- Inputs: `nixpkgs` (one channel, chosen deliberately: `nixos-YY.MM` stable or `nixos-unstable`) and `home-manager` (matching release branch, with `inputs.nixpkgs.follows = "nixpkgs"`).
- Every extra input must set `inputs.nixpkgs.follows = "nixpkgs"`. Add Hyprland or Quickshell flake inputs only when a needed feature is missing from nixpkgs; mismatched Mesa/Qt/Wayland libraries cause crashes.
- Pass `inputs`, `username` and `hostname` through `specialArgs` (and `home-manager.extraSpecialArgs`). Never hardcode a username, hostname, or `/home/<user>` path in shared modules.
- Flakes only see files tracked by git. After creating a file, `git add` it before building.
- Commit `flake.lock`. Update inputs only on request: `nix flake update` (all) or `nix flake update <input>` (one), then rebuild and commit lock + config together.

**Hosts and hardware**

- `hardware-configuration.nix` is generated by `nixos-generate-config` and is never hand-edited or imported from shared code. On a new machine it is regenerated, never copied.
- Hardware quirks (GPU drivers, firmware, `boot.kernelParams`, microcode, TLP/power profiles, fingerprint) go in `hosts/<name>/default.nix`.
- `system.stateVersion` is set once per host at install time and never changed. It is not the NixOS version; upgrading NixOS means changing the nixpkgs input.

**Nix daemon and store hygiene** (in `modules/nixos/core.nix`)

- `nix.settings.experimental-features = [ "nix-command" "flakes" ];` and `nix.settings.auto-optimise-store = true;`.
- Enable `nix.gc` (automatic, weekly, e.g. `--delete-older-than 14d`) and cap `boot.loader.*.configurationLimit` (\~10) so `/boot` doesn't fill up.
- Extra binary caches go in `nix.settings.substituters` + `trusted-public-keys`, only for inputs actually used.

**Applying changes**

| Command | When to use |
| --- | --- |
| `nixos-rebuild build --flake .#<host>` | Check it builds, change nothing |
| `nixos-rebuild test --flake .#<host>` | Try it live; reboot reverts it |
| `nixos-rebuild switch --flake .#<host>` | Apply now and make it the boot default |
| `nixos-rebuild boot --flake .#<host>` | Apply at next boot (kernel, login manager changes) |
| `nixos-rebuild build-vm --flake .#<host>` | Test risky changes in a VM |

- Claude Code runs `build`/`dry-build` itself; I run `switch`/`boot` (needs sudo).
- Every switch creates a generation; a broken system is fixed by picking the previous generation in the boot menu or `nixos-rebuild switch --rollback`.

**Secrets**

- The Nix store is world-readable. Never put passwords, Wi-Fi PSKs, tokens or keys in any `.nix` file or string that ends up in the store.
- When secrets are needed, use sops-nix or agenix (decrypted at activation into `/run`), and reference them by path. Use `hashedPasswordFile` / `hashedPassword` for users, never `password`.

## Home Manager policies

Home Manager is imported as a NixOS module (`home-manager.nixosModules.home-manager`), never run standalone.

- Set `home-manager.useGlobalPkgs = true;` and `home-manager.useUserPackages = true;` so user packages come from the system's nixpkgs.
- Set `home-manager.backupFileExtension = "hm-bak";` so an existing file in `~/.config` doesn't block activation.
- `home.stateVersion` is set once in `hosts/<name>/home.nix` and never changed.
- User-level things live in Home Manager (`modules/home/`): user packages, shell, git, apps, dotfiles. System-level things live in `modules/nixos/`: services, drivers, login manager, `programs.hyprland`.
- Prefer a Home Manager `programs.<app>` module when it exists and the config is stable. Use raw files in `dotfiles/` for anything I iterate on (Hyprland, Quickshell).

**Linking dotfiles** (the hot-reload pattern)

- Link files from the live git checkout with `config.lib.file.mkOutOfStoreSymlink`, so edits apply on save without a rebuild:

```nix
# modules/home/quickshell.nix
{ config, ... }:
let repo = "${config.home.homeDirectory}/nixos-config";
in {
  xdg.configFile."quickshell".source =
    config.lib.file.mkOutOfStoreSymlink "${repo}/dotfiles/quickshell";
}
```

- The repo path is derived from `config.home.homeDirectory`, never hardcoded. The repo must be cloned to `~/nixos-config`.
- Link `dotfiles/hypr/*` one file at a time (`xdg.configFile."hypr/binds.lua"`, …) so the host can still generate `hypr/host.lua` next to them.
- Use plain `source = ./file` (copied into the store) only for config that never changes or needs Nix-substituted values.

## Hyprland policies

Hyprland 0.55, from the single stable nixpkgs channel, is installed by the NixOS module and configured by raw **Lua** files in `dotfiles/hypr/`. hyprlang (`.conf`) is deprecated since 0.55, so don't write it for Hyprland itself. hypridle and hyprpaper keep their own `.conf` files.

**Installation** (in `modules/nixos/desktop.nix`)

- `programs.hyprland.enable = true;` and `programs.hyprland.withUWSM = true;` (UWSM is the recommended systemd session manager). The module also sets up the session file, `xdg-desktop-portal-hyprland` and polkit.
- Add `xdg-desktop-portal-gtk` to `xdg.portal.extraPortals` for file pickers. Don't add a second Hyprland portal.
- `environment.sessionVariables.NIXOS_OZONE_WL = "1";` so Electron/Chromium apps run natively on Wayland.
- Use the nixpkgs Hyprland from the one stable channel; no second nixpkgs input. If the flake input is ever added: configure `hyprland.cachix.org` first, set both `programs.hyprland.package` and `portalPackage` from the flake, and make plugins follow the `hyprland` input.
- If the Home Manager module `wayland.windowManager.hyprland` is ever used, set its `systemd.enable = false` (it conflicts with UWSM) and `package = null; portalPackage = null;` so the NixOS module's versions are used.
- Ecosystem pieces, each optional: `hypridle` (idle/suspend), `hyprpaper` (wallpaper). No `hyprlock` or `hyprpolkitagent`: the lock screen is Quickshell (`panels/lock/`, PAM service `quickshell`) and polkit prompts come from Quickshell's built-in agent (`services/Polkit.qml`, shown by the island). Any lock screen needs a PAM service (`security.pam.services.<name> = {};`).

**Config layout**

- `hyprland.lua` is the entry point. It runs `require("colors")`, `require("binds")` and the other modules, holds the general/input/decoration settings in `hl.config({ … })`, and loads `~/.config/hypr/host.lua` last with `dofile`. One topic per file.
- Verified Lua behaviour in 0.55:
  - Each `require()` runs in its own scope, so share values by `return`ing a table (see `colors.lua`).
  - Hyprland resolves the `hyprland.lua` symlink, so `require` searches `dotfiles/hypr/`, and absolute names don't work. Load files outside the repo with `dofile`.
  - The API reference is the stub file shipped in the package, `share/hypr/stubs/hl.meta.lua`, plus the example `share/hypr/hyprland.lua`.
- Define reusable values as Lua locals at the top (`local mod = "SUPER"`, `local terminal = …`) and use them in binds.
- Shared config never names a physical screen. It keeps only a fallback `hl.monitor({ output = "", mode = "preferred", … })`; real monitors (`eDP-1`, resolution, refresh, scale) come from the host's generated `host.lua`. Same for per-device `hl.device` overrides.
- Bind with the right options: plain `hl.bind(keys, dispatcher)` for normal keys, `{ mouse = true }` for mouse drag, `{ locked = true, repeating = true }` for keys that repeat and also work on the lock screen (volume, brightness), `{ locked = true }` for the lid switch and media keys.
- Use `hl.on("hyprland.start", …)` in `autostart.lua` for startup apps, launched as `uwsm app -- <cmd>` so they get proper systemd scopes. Long-running daemons (Quickshell, hypridle) are better as user systemd services from Home Manager.
- With UWSM, environment variables go in `~/.config/uwsm/env` (all sessions) or `env-hyprland`, not in `hl.env(…)` calls in `hyprland.lua`.
- Colors live only in `colors.lua` (`return { accent = "rgb(…)" }`); other files `require` it.
- For now Hyprland stays minimal and functional: no animations, blur, shadows or rounding. Don't add them unless I ask.

**Version awareness**

- Window-rule and some keyword syntax changes between Hyprland releases. Before writing rules, check `hyprctl version` and use the matching versioned wiki page (`https://wiki.hypr.land/<version>/…`). Don't mix old and new rule syntax.
- After a Lua edit, `Hyprland --verify-config -c ~/.config/hypr/hyprland.lua` must print `config ok`. Then `hyprctl reload` (usually automatic on save) and `hyprctl configerrors` must return nothing. With Lua, `hyprctl keyword` is rejected; use `hyprctl eval '<lua>'` and `hyprctl dispatch 'hl.dsp.…'`. Use `hyprctl monitors` / `hyprctl clients` to read real names and classes instead of guessing.

## Quickshell policies

The desktop UI is one Quickshell config at `dotfiles/quickshell/`, linked to `~/.config/quickshell` and hot-reloaded on save.

**Packaging**

- Use `pkgs.quickshell` from nixpkgs. A flake input is allowed only for an unreleased feature, pinned with `?ref=<tag>` and `inputs.nixpkgs.follows = "nixpkgs"` (mismatched system libraries crash).
- Icons: every icon in the project comes from the **Colloid** icon theme (variant `Colloid-Dark`, `pkgs.colloid-icon-theme`, installed in `modules/nixos/icons.nix`).
  - In QML, use `Quickshell.iconPath("<freedesktop-name>")` (the `//@ pragma IconTheme Colloid-Dark` line at the top of both entry files selects the theme). Don't ship icon files.
  - GTK apps get the theme from `modules/home/gtk.nix`, and hyprtoolkit apps from `dotfiles/hypr/hyprtoolkit.conf`.
  - The SDDM theme gets Colloid's `status/symbolic` folder linked in as `assets/icons` by `modules/nixos/sddm/default.nix`.
  - Before using a name, check that it exists under `/run/current-system/sw/share/icons/Colloid-Dark/`.
- Add optional Qt modules only when used: `qtsvg` (SVG icons; already part of the nixpkgs Quickshell package), `qtimageformats` (WEBP), `qtmultimedia` (audio/video), `qt5compat` (avoid; prefer `MultiEffect` for blur).
- Run Quickshell as a user systemd service (Home Manager) bound to the graphical session, not as `exec-once`.

**Structure and QML conventions**

- `shell.qml` (root `ShellRoot`) only wires panels together; no UI logic lives there. Since `~/.config/quickshell/shell.qml` exists, do not create named sub-configs. Quickshell only resolves imports inside the entry file's folder.
- The lock screen (`components/LoginScreen.qml`) copies the look of the SDDM login theme (`modules/nixos/sddm/theme`). SDDM can't run Quickshell, so the two are separate code: when the look changes, change both.
- The login manager is SDDM, launching the `hyprland-uwsm` session. Don't replace it with greetd: a greetd + Hyprland + Quickshell greeter was tried and broke login.
- One component per file, `PascalCase.qml`, so it is usable as a type by name. Lowercase folder names. Import folders with relative `import "../components"`. Do not use `root:/` imports (they break the LSP and singletons).
- Shared state and system data live in singletons (`pragma Singleton` + `Singleton` root) under `services/` (e.g. `Audio`, `Battery`, `Network`, `Notifs`). Panels read from services; they never spawn their own processes.
- Multi-monitor: wrap per-screen windows in `Variants { model: Quickshell.screens }` and take the screen from `modelData`. Keep `Process`, `Timer` and other shared objects outside the delegate so they aren't duplicated per screen.
- Components take inputs via `required property`. IDs aren't visible across files; share state through properties or singletons.
- Bars/overlays use `PanelWindow` with `anchors` and `implicitHeight`/`exclusiveZone`; normal windows use `FloatingWindow`. Load rarely shown panels (launcher, control center) lazily with `LazyLoader`.
- Prefer built-in Quickshell services (Pipewire, UPower, Notifications, SystemTray, Hyprland IPC, Mpris) over shelling out. When a command is unavoidable, use `Process` with an argument array (never a shell string) and `StdioCollector`.
- Battery-friendly: `SystemClock` with `precision: SystemClock.Minutes` unless seconds are shown; no fast polling timers when an event source exists.
- Never hardcode hardware paths (`/sys/class/backlight/intel_backlight`, `BAT0`) or monitor names; detect them or read them from a service.

**Theme tokens (single source of truth)**

- All colors, fonts, sizes, spacing, radii and animation durations live in `theme/Theme.qml` as readonly properties. Components never contain literal colors or pixel values.
- `dotfiles/hypr/colors.lua` holds the same palette for Hyprland. When a color changes, change both in the same commit. (Later option: generate both from one file with Nix.)

**Tooling**

- Create an empty `.qmlls.ini` next to `shell.qml` (Quickshell fills it in) and keep it in `.gitignore`. Fix every qmlls warning.
- Check `quickshell log` / the terminal output after each edit; a reload that prints errors counts as broken.

## Workflows

**Daily edit loop**

1. Hyprland or Quickshell change: edit the file in `dotfiles/`, save, it reloads. Check `hyprctl configerrors` or the Quickshell log. No rebuild.
2. Nix change: edit the module, `git add` any new file, run `nix flake check` and `nixos-rebuild build --flake .#<host>`. I run `sudo nixos-rebuild switch --flake .#<host>`.
3. Commit small, one topic per commit (`hypr: add screenshot binds`, `nixos: enable bluetooth`).

**Adding a new laptop**

1. Install NixOS from the ISO; enable flakes temporarily if needed.
2. `git clone <repo> ~/nixos-config`.
3. `mkdir hosts/<new>` and `nixos-generate-config --show-hardware-config > hosts/<new>/hardware-configuration.nix`.
4. Copy `default.nix` and `home.nix` from an existing host; change hostname, keep the new machine's `system.stateVersion` / `home.stateVersion`, set its monitors and hardware quirks.
5. Add the host to `nixosConfigurations` in `flake.nix` (one line).
6. `git add .` then `sudo nixos-rebuild switch --flake .#<new>`, reboot.

**Updating**

1. `nix flake update`, then `nixos-rebuild build --flake .#<host>`.
2. If it builds, I switch and test the desktop; if something breaks, roll back and pin or revert the lock.
3. Commit `flake.lock` alone (`flake: update inputs`).
4. Changing NixOS release = change the nixpkgs and home-manager branch together; never touch `stateVersion`.

## Don'ts for Claude Code

- Don't edit `hardware-configuration.nix`, `flake.lock` (except via `nix flake update`), or any `stateVersion`.
- Don't import anything from `hosts/` into `modules/` or `dotfiles/`.
- Don't hardcode usernames, hostnames, `/home/<user>`, monitor names, or `/sys` device paths in shared files.
- Don't add packages with `nix-env`, `nix profile`, or by editing files outside the repo.
- Don't put secrets in the repo or in any Nix string.
- Don't add flake inputs without `follows`, and don't add Hyprland/Quickshell flake inputs without asking.
- Don't introduce frameworks (flake-parts, snowfall, haumea) or `options` layers without asking.
- Don't convert `dotfiles/` into Nix-generated config (`wayland.windowManager.hyprland.settings`) without asking; it kills hot reload.
- Don't put literal colors or sizes in QML components; use `Theme`.
- Don't run `sudo nixos-rebuild switch`, `nix-collect-garbage -d`, or anything that deletes generations; ask me.
- Don't say a change works until it built (`nixos-rebuild build`) or reloaded without errors.
